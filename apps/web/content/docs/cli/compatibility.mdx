## Supported Stack Options

The CLI supports TanStack Router, TanStack Start, or no frontend.

The supported backend choices are Hono, Elysia, TanStack Start fullstack (`self`), or no backend. Data options are SQLite or PostgreSQL with Drizzle, or no database.

## Frontend and Backend

- `self` uses TanStack Start server routes and requires `tanstack-start` in `--frontend`.
- Hono and Elysia run as separate backend services and can be paired with either TanStack frontend.
- `--backend none` disables API, database, ORM, auth, and runtime setup.
- `--frontend none` creates a backend-only project.

## Runtime and Database

- Cloudflare Workers supports Hono and SQLite.
- `--runtime none` is available with backend `none` or `self`.
- Drizzle supports SQLite and PostgreSQL.
- `--database none` requires `--orm none`.
- Cloudflare D1 requires SQLite and either a Workers server deployment or TanStack Start fullstack with Cloudflare web deployment.
- Turso and D1 are SQLite setups. Neon, Supabase, Prisma Postgres, and PlanetScale provide PostgreSQL. Docker starts a local PostgreSQL database.

## API and Authentication

Both tRPC and oRPC are supported with TanStack frontends. `--api none` disables API scaffolding.

Better Auth and Clerk are supported. Better Auth requires a backend, and Clerk can be used with Hono, Elysia, or TanStack Start fullstack. Select `--auth none` to skip authentication.

## Addons and Examples

- PWA is available with TanStack Router.
- Tauri and Electrobun support TanStack Router and TanStack Start. They require a separate backend or no backend; they cannot package TanStack Start's server routes.
- Turborepo and Vite+ are mutually exclusive task runners.
- The todo example requires a database and an API layer.
- The AI example requires a backend.

Use `create-better-tanstacked schema --name all` or the `bts_get_schema` MCP tool to inspect the current machine-readable options.
