## Overview

[Alchemy](https://alchemy.run) is the infrastructure-as-code layer generated when you choose **Cloudflare** or **Prisma** as a deployment target. The CLI writes a `packages/infra` workspace containing:

- one `alchemy.run.ts` for applications, managed databases, and migrations
- root `dev`, `deploy`, and `destroy` commands

## Supported deployment shapes

Cloudflare supports TanStack Router and TanStack Start web apps, plus a separate Hono server on the Workers runtime. Full-stack `backend: self` projects deploy as one TanStack Start web application.

The Prisma deployment target supports:

- web: TanStack Router and TanStack Start
- server: Hono and Elysia on Bun or Node
- mixed stacks, such as Cloudflare web + Prisma server or Prisma web + Cloudflare server

The CLI rejects unsupported framework/runtime combinations before writing files.

```bash
# Full-stack TanStack Start on Prisma with Neon Postgres
bunx create-better-tanstacked@latest my-app \
  --frontend tanstack-start \
  --backend self \
  --runtime none \
  --database postgres \
  --orm drizzle \
  --db-setup neon \
  --web-deploy prisma

# TanStack Router on Cloudflare with a Hono/Workers server and D1
bunx create-better-tanstacked@latest my-app \
  --frontend tanstack-router \
  --backend hono \
  --runtime workers \
  --database sqlite \
  --orm drizzle \
  --db-setup d1 \
  --web-deploy cloudflare \
  --server-deploy cloudflare
```

## Provider login

Install dependencies, then let Alchemy configure every provider used by the stack:

```bash
bun install
cd packages/infra
bunx alchemy profile edit
```

Alchemy stores provider profiles under `~/.alchemy`. For Alchemy-managed databases, it creates the database and supplies the connection details to your application.

## Managed databases

Alchemy can create and manage Neon, PlanetScale, and Prisma Postgres databases when the backend deploys to Cloudflare or Prisma:

- `backend: self`: the web deployment owns the database
- separate backend: the server deployment owns the database

If the backend deploys elsewhere, configure its database separately.

| Setup                | What Alchemy creates                   |
| -------------------- | -------------------------------------- |
| Neon                 | A project and database connection      |
| PlanetScale Postgres | A database and application credentials |
| Prisma Postgres      | A project, database, and connection    |
| Cloudflare D1        | A database bound to your Worker        |

<Callout type="warn">
  PlanetScale can charge for `PS_DEV` databases. Review `clusterSize` in
  `packages/infra/alchemy.run.ts` before deploying.
</Callout>

## Migration workflow

After changing your database schema, generate a migration:

```bash
# Drizzle: generate SQL from the current schema
bun run db:generate
```

Review and commit the generated migration files. Alchemy applies migrations for managed databases during deployment.

## Develop and deploy

Run these commands from the project root:

```bash
bun run dev
bun run deploy
bun run destroy
```

- `dev` starts local development.
- `deploy` builds and deploys your applications and managed resources.
- `destroy` removes the resources in the selected stage, including managed databases.

Deployments are staged. For an explicit production stage:

```bash
cd packages/infra
bunx alchemy deploy --stage production
```

Use the same stage when destroying it:

```bash
bunx alchemy destroy --stage production
```

## Environment variables

Set infrastructure configuration in `packages/infra/.env` and application configuration in the relevant app's `.env` file. Alchemy supplies managed database connections and deployed application URLs automatically.

Keep secrets out of version control. Run `bun run deploy` after changing deployment configuration.

## Customize your infrastructure

Edit `packages/infra/alchemy.run.ts` to change regions, database sizes, or add resources. See the [Alchemy documentation](https://alchemy.run) for the available resources and options.
