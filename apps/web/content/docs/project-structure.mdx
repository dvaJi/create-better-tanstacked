## Overview

Better-T-Stack creates a Bun, npm, or pnpm workspace with `apps/*` for runnable applications and `packages/*` for shared code. The generated files depend on the frontends, backend, API, database, auth, addons, and deployment choices.

## Root Layout

```text
my-app/
├── apps/
├── packages/
├── package.json
├── bts.jsonc
└── turbo.json        # when Turborepo is selected
```

- `bts.jsonc` stores the chosen stack and lets `create-better-tanstacked add` detect the project.
- `turbo.json` is added by the Turborepo addon. Vite+ writes its own root config and scripts.
- Workspace files such as `pnpm-workspace.yaml`, `bunfig.toml`, and `.npmrc` depend on the package manager.
- `packages/config` is always created. `packages/infra` is added for supported Alchemy deployment targets.

## Applications

### TanStack web

Choose `tanstack-router` for a client-side web app or `tanstack-start` for server rendering and server routes. Both live in `apps/web` and use the shared `packages/ui` package for shadcn/ui components when generated.

TanStack Router routes are in `apps/web/src/routes`. TanStack Start routes are in `apps/web/src/routes` and its server functions live alongside the app. With `--backend self`, TanStack Start provides the backend routes and no separate `apps/server` app is created.

### Expo native

Choose `native-bare`, `native-uniwind`, or `native-unistyles` to add `apps/native`. Each option uses Expo Router; Uniwind and Unistyles add their respective styling setup.

A project can include one Expo frontend alongside one TanStack web frontend.

### Hono or Elysia server

Choosing Hono or Elysia adds `apps/server`. The server entrypoint and API or auth adapters are generated there according to the selected options. Hono can also use the Cloudflare Workers runtime.

## Shared Packages

- `packages/api`: generated when tRPC or oRPC is selected.
- `packages/auth`: generated when Better Auth or Clerk is selected.
- `packages/db`: generated when a database and Drizzle are selected. Drizzle schemas and migration files are kept here.
- `packages/ui`: shared React UI components used by the web app.
- `packages/infra`: Alchemy configuration for Cloudflare or Prisma deployment.

The todo example requires a database and API. The AI example adds its client and server files to the selected apps.

## Addon Applications and Config

- `apps/desktop` is added by Tauri or Electrobun when a web frontend is selected.
- `apps/fumadocs` is added by the Fumadocs addon.
- OpenTUI and WXT add their app files and dependencies based on their selected templates.
- Oxlint and Vite+ add lint and format configuration. Lefthook adds Git hook configuration.

## Development Scripts

Root scripts run commands across the workspace. Turborepo uses `turbo run`; Vite+ uses `vp run`; without a task runner, the selected package manager runs each workspace package directly. Common scripts include `dev`, `build`, `check-types`, and `dev:web` or `dev:server` when those apps exist.

Database scripts such as `db:push`, `db:generate`, and `db:studio` are added when Drizzle and a supported database are selected. Database hosting setup can add local Docker Compose files or provider-specific configuration.

This page describes the generated TanStack, Expo, Hono/Elysia, Drizzle, and supported addon layouts.
